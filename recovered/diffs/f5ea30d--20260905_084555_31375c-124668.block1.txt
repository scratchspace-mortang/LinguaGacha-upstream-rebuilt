    fix(harper): prevent re-render loop on identical spelling activity snapshots
    
    Previously, applySpellingActivitySnapshot always created a new snapshot
    object even when the incoming snapshot had the same revision and identical
    pending/active values as the current one.  useSyncExternalStore detects this
    as a state change (reference inequality) and schedules a re-render, which
    can cascade into an infinite render loop under certain conditions (e.g.
    when a falling-edge refresh races with an SSE re-emission of the same
    snapshot).
    
    The fix adds a structural-equality guard (revision + pending + active) that
    skips re-assignment when the incoming snapshot is identical to the current
    one, preventing the new-reference trigger.
    
    Also adds applySpellingActivitySnapshot to the mock DesktopEventStreamOptions
    in desktop-event-stream.test.tsx and the DesktopStateStores stub in
    use-desktop-state.test.tsx so both test files type-check cleanly.
    
    Addresses: Maximum update depth exceeded errors during spelling activity
    state transitions when a batch ends or a spellcheck is re-run.
