    fix(frontend): defer listener notify via setTimeout(0) to prevent React max-update-depth crash
    
    Coalesce rapid same-tick applySnapshot dispatches into one notification.
    
    The Re-spellcheck SSE path triggers multiple applySnapshot calls
    synchronously in the same event-loop tick, which in React 19 can
    overwhelm the nested-update guard even when the structural-equality
    guard skips re-assignment — the listener list was still iterated per
    call, flooding React's update counter.
    
    Fix: schedule listener-notify via setTimeout(0) so all synchronous
    applySnapshot calls in the same tick share one notification pass.
    
    Fixes 'Maximum update depth exceeded' React error during Re-spellcheck
    (cf. https://github.com/esengine/DeepSeek-Reasonix/issues/2123).
    
    Test: added batching contract test with vi.useFakeTimers;
    updated existing test expectations to reflect coalesced notification.
